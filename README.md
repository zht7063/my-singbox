# My sing-box

Build sing-box based Shadowsocks 2022 and VLESS-Reality-Vision nodes with Docker on a Debian/Ubuntu VPS, and export a `clash.yaml` for Mihomo.

## What gets deployed

- Shadowsocks 2022 (`2022-blake3-aes-128-gcm`), port `8388`, TCP and UDP.
- VLESS + REALITY, with `flow` set to `xtls-rprx-vision`, port `8443`, TCP only. The server's default SNI is `www.microsoft.com`.
- Container image `ghcr.io/sagernet/sing-box:latest`, with `network_mode: host`.
- The client config is `clash.yaml`. The nodes are `shadowsocks` and `vless-reality`, both in the `select` group `Proxy` (default: `shadowsocks`).

> **Upgrading from an older version:** the nodes were previously named `My-sing-box` and `My-VLESS-Reality`, and the group `PROXY`. They were renamed. Server ports and credentials are unchanged, but an existing `clash.yaml` keeps the old names. To get the new names, delete `clash.yaml`, run `bash scripts/conf-clash.sh` again, and **re-import `clash.yaml` in every client** (a client's saved node and group selection is lost when names change).

Ports `8388` and `8443` must be free. The ports are defined in `templates/config.json.template` and `templates/clash.yaml.template`. `compose.yaml` does not map ports.

## Requirements

- Debian/Ubuntu. The deployment directory must be writable; all files live in `/opt/sing-box/`.
- Docker, the Docker Compose plugin (`docker compose version`), and a running Docker daemon.
- On Debian/Ubuntu, run `sudo bash scripts/init.sh` first. It installs only the missing non-Docker dependencies (`ca-certificates`, `curl`, `openssl`, `iproute2` which provides `ss`, `git`; it also installs `awk`, `grep`, or `coreutils` if they are missing). It does not install Docker, and it does not change SSH, the firewall, users, or passwords.
- openssl and curl (`gen-keys.sh` accepts wget when curl is missing). An interactive terminal is needed only when public IP detection fails.
- `ss` (`iproute2`). Without it, `start.sh` only warns and skips the UDP check.
- Open `8388/tcp`, `8388/udp`, and `8443/tcp` in the firewall and the security group.
- The client must use the Mihomo core, for example Clash Verge, FlClash, or Clash Meta.

## Quick start

```bash
git clone https://github.com/zht7063/my-singbox.git /opt/sing-box
cd /opt/sing-box
sudo bash scripts/init.sh
SING_BOX_VERSION=latest bash scripts/gen-keys.sh
bash scripts/gen-config.sh
bash scripts/conf-clash.sh
bash scripts/start.sh
```

If `git` is not installed yet, run `sudo apt-get update && sudo apt-get install -y git` first, then clone. `init.sh` also installs `git` later on.

`SING_BOX_VERSION` only decides which image `gen-keys.sh` uses to generate the keys. The running container always uses `ghcr.io/sagernet/sing-box:latest` from `compose.yaml`.

| Script | Behavior | Output |
| --- | --- | --- |
| `scripts/init.sh` | Debian/Ubuntu only, and must run as root (otherwise it tells you to rerun with `sudo`). After `apt-get update`, it installs only the missing non-Docker dependencies and prints whether each tool is present. If Docker or Compose is unavailable, it points you to the appendix. | No project files |
| `scripts/gen-keys.sh` | Checks `docker`, `openssl`, and `docker info`. Uses curl (or wget if curl is missing) to query a public IP echo service, trying IPv4 first and falling back to IPv6 if there is no public IPv4. On success it prints the detected address. Only on failure does it ask `Public IP address of this machine:`. Private, loopback, and reserved addresses are rejected. It then uses the sing-box image to generate the UUID, the REALITY keys, and the Shadowsocks 2022 password. | `.env` |
| `scripts/gen-config.sh` | Renders the server template from `.env`. The config contains neither `REALITY_PUBLIC_KEY` nor `SERVER_ADDRESS`. | `config.json` |
| `scripts/conf-clash.sh` | Renders the client template from `.env`. The routing rules are kept as they are. It refuses to write the REALITY private key. | `clash.yaml` |
| `scripts/start.sh` | Runs `docker compose up -d` and confirms the container `sing-box` stays running. | A running sing-box |

If the three output files already exist, the corresponding scripts refuse to overwrite them. To regenerate one, delete that file first.

## Verify, roll back, uninstall

`scripts/start.sh` runs `sing-box check` inside the container, checks TCP on `127.0.0.1` for every `listen_port`, and checks UDP on `8388` with `ss -uln`. Without `ss` it only warns and does not fail. On success it prints `Self-check passed. Ports: ...`. This covers the local machine only. For clients to connect, the three ports above must still be open on the public side.

If `latest` fails to start or `sing-box check` fails, change the image in `compose.yaml` to:

```yaml
image: ghcr.io/sagernet/sing-box:1.14.4
```

Then run `docker compose up -d` in `/opt/sing-box`. If the keys also need to be generated by `1.14.4`, first delete `.env`, `config.json`, and `clash.yaml`, then rerun the four scripts in order with `SING_BOX_VERSION=1.14.4`, and make `compose.yaml` use the same tag.

Uninstalling only stops the container of this directory. It does not delete the repository:

```bash
cd /opt/sing-box
docker compose down
```

## Optional: ISP outbound (static SOCKS5 egress)

`scripts/isp-outbound.sh` is optional. Skip it and nothing changes: the three nodes keep using `8388` and `8443`, and no other script depends on it. Use it when you have a static ISP SOCKS5 proxy and want two extra ports whose traffic leaves through that proxy instead of the server's own IP.

```bash
cd /opt/sing-box
sudo bash scripts/isp-outbound.sh            # menu: add / remove
sudo bash scripts/isp-outbound.sh --add      # add or update
sudo bash scripts/isp-outbound.sh --remove   # remove everything it added
```

It must run as root (it exits otherwise) and installs `jq` with `apt-get` if `jq` is missing. It asks for the proxy address (`IPv4:port` or `[IPv6]:port`), username and password, and an optional expected egress IP.

| Added | Port | Goes out through |
| --- | --- | --- |
| sing-box inbound `ss-isp-in` (clone of `ss-in`, same method and password) | `13839` tcp+udp | the SOCKS5 proxy |
| sing-box inbound `vless-reality-isp-in` (clone of `vless-reality-in`, same UUID and keys) | `18444` tcp | the SOCKS5 proxy |

Traffic is routed by inbound tag, so `8388` and `8443` still go out directly. If the SOCKS5 proxy goes down, the ISP ports fail; they never fall back to a direct connection.

What `--add` does, in this order. If any step before the restart fails, nothing has been written:

1. Tests the proxy with a SOCKS5 TCP request (credentials are passed to `curl` on stdin, never on the command line) and compares the egress IP it reports with `ISP_SOCKS_EGRESS_IP` if you set one, otherwise with the proxy's entry IP. A mismatch stops the run.
2. Builds the new `config.json`, `.env` and `clash.yaml` in temporary files and validates the config with `sing-box check` using the image your container runs.
3. Backs up all three files to `.isp-backup/<timestamp>/` (the last 5 are kept).
4. Replaces `config.json`, then `docker compose up -d --force-recreate` and checks that the container is running and the new ports listen. On failure it restores all three files and recreates the container again.
5. Writes `.env` and `clash.yaml`, then opens the three ports in the local firewall: `ufw` or `firewalld` (both persist natively), or `iptables` rules saved through `netfilter-persistent`, which is installed when it is missing. With no active firewall it does nothing. If a firewall step fails the script exits non-zero and lists the ports to open by hand; re-running `--add` finishes the job.
6. Reminds you to open the same ports in your cloud provider's security group. The script cannot do that for you.

Running `--add` twice with the same values changes nothing, and `--remove` after `--add` restores `config.json`, `.env` and `clash.yaml` byte for byte (it also closes the firewall ports it opened).

Notes:

- `.env` gets four optional keys: `ISP_SOCKS_ADDR`, `ISP_SOCKS_USER`, `ISP_SOCKS_PASS` and `ISP_SOCKS_EGRESS_IP`. The username and password are stored as `b64:<base64>`, because Docker Compose also reads `.env` and would otherwise mangle characters such as `$`. The password is never printed or put on a command line.
- `clash.yaml` gets two new nodes, `shadowsocks-isp` and `vless-reality-isp`, and a new `select` group `Proxy-ISP` that contains them. They sit between `# BEGIN my-singbox-isp` and `# END my-singbox-isp` markers. The `Proxy` group and every rule stay as they are, so nothing is routed to `Proxy-ISP` unless you pick it in the client. **Re-import `clash.yaml` in your clients afterwards.**
- The script finds the source nodes only by their current names, `shadowsocks` and `vless-reality`. If your `clash.yaml` was generated before the rename, it stops with a hint; delete `clash.yaml` and run `scripts/conf-clash.sh` again.
- Only TCP through the proxy is tested. Shadowsocks UDP on `13839` works only if the SOCKS5 proxy supports UDP ASSOCIATE.
- Only one run at a time (lock file `.isp.lock`). Runtime files `.isp-backup/`, `.isp.lock` and `.isp-tmp.*` are in `.gitignore`.

## Credentials

`.env`, `config.json`, and `clash.yaml` contain node credentials and are listed in `.gitignore`. The three scripts set the corresponding file to mode `600`. The REALITY private key appears only in `.env` and `config.json`, and is never written to `clash.yaml`. Do not commit these files.

## Appendix: Quick Docker installation

`init.sh` does not install Docker. The three steps below follow the apt repository installation in the official [Debian](https://docs.docker.com/engine/install/debian/) and [Ubuntu](https://docs.docker.com/engine/install/ubuntu/) documentation, and use the `ID` in `/etc/os-release` to tell the distributions apart.

Remove old packages that conflict with the official ones. The package names are the union of the two documents, so Debian and Ubuntu use the same command. If none of these packages are installed, `apt-get remove` removes nothing.

```bash
sudo apt-get remove -y $(dpkg --get-selections docker.io docker-compose docker-compose-v2 docker-doc docker-buildx podman-docker containerd runc | cut -f1)
```

Add the official Docker apt source: write the GPG key, and pick the `debian` or `ubuntu` repository according to `ID`. For the suite name, use `UBUNTU_CODENAME` on Ubuntu, otherwise `VERSION_CODENAME`.

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL "https://download.docker.com/linux/$(. /etc/os-release && echo "$ID")/gpg" -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
. /etc/os-release
sudo tee /etc/apt/sources.list.d/docker.sources >/dev/null <<EOF
Types: deb
URIs: https://download.docker.com/linux/${ID}
Suites: ${UBUNTU_CODENAME:-$VERSION_CODENAME}
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
sudo apt-get update
```

Install Docker Engine, the CLI, containerd, the Buildx plugin, and the Compose plugin.

```bash
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```
