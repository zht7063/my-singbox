# TUI 使用指南

TUI 是现有 TypeScript CLI 的交互入口。它共享配置生成、端口模型和 ISP 操作能力，适用于 Debian / Ubuntu VPS；在其他系统上可以打开界面查看诊断，但部署检查会阻止执行。

## 启动

从源码运行：

```bash
npm ci
npm run build
# 切换到可写的部署目录后，使用实际仓库路径：
node /path/to/my-singbox/dist/cli.js tui
```

全局安装包含此功能的版本后：

```bash
my-singbox tui
```

终端需要交互式 stdin/stdout、至少 60 列 × 18 行，且不能是 `TERM=dumb`。重定向和管道请继续使用 `doctor`、`init`、`isp-outbound` 等文本命令。设置 `NO_COLOR=1` 可禁用颜色。

## 页面与键盘

- **状态首页**：区分空部署、已有完整配置、文件缺失与配置不一致。显示未完成的部署/ISP 操作记录。页面中的服务状态没有检查时会明确说明。
- **运行条件**：检查 Node、Linux/glibc、发行版、架构、目录、Docker CLI、Compose v2、当前 Docker 目标、daemon 和可选的 ss。启用 ISP 时增加 curl 检查；程序不执行安装建议。
- **首次部署**：确认地址与 SS/VLESS 端口，主动检查本机占用，可生成高位端口建议并手动接受，再选择是否启用 ISP。预览通过后才创建配置、拉取所需镜像并启动。
- **ISP**：添加、更新、移除均先预览；已有凭据通过“保留 / 修改”表达。代理支持 IPv4 / 严格 IPv6，用户名和密码均必填。保留凭据取自 `.env`，与 `config.json` 不一致会提示。
- **结果与详情**：列出完成阶段、警告、跳过项和脱敏日志；长详情可分页查看。已有部署的监听端口首版只读。

Tab / Shift+Tab 移动焦点，菜单内也可用方向键。Enter 在输入框内进入下一项，在按钮上执行该动作；不会从普通输入框直接提交部署。Esc 返回，有草稿时先确认丢弃；Ctrl+C 在执行前退出，在执行中请求安全停止与必要的恢复。

输入框支持左右方向键、Ctrl+A/E 到开头/结尾，以及 Ctrl+U/K 删除光标前/后内容。中文、emoji、组合字符按 grapheme 编辑。密码默认隐藏；Ctrl+R 临时显示当前正在输入的凭据，失焦或 10 秒后隐藏。粘贴的非法控制字符不会执行命令，会在字段校验时报错。

## 端口和检查结果

Shadowsocks 同时需要 TCP 和 UDP，VLESS 需要 TCP。默认分别为 8388 和 8443；两个端口不能相同。新部署会将自定义端口写入 `.env` 的 `SS_PORT` / `VLESS_PORT`，服务端和客户端使用同一模型生成。

“未发现占用”只表示本次本机监听表或临时绑定测试的结论，不能保证提交时仍可用，也不证明外网可达。提交前会重新检测；未知结果需要明确选择接受，确定冲突则阻止操作。已有服务的监听信息来自配置文件，页面不会把它误标为已经检查过归属。

缺少 ss 时，预部署检查可降级为独占绑定探测；启动后的 UDP 检查仍可能跳过。跳过项与外网尚未验证的信息会保留在结果中。程序不修改防火墙或云安全组，需自行开放结果页中的实际端口。

## ISP 测试的含义

“测试代理”通过配置的 SOCKS5 代理请求 HTTPS 出口 IP 查询服务（api.ipify.org、ipinfo.io、ipv4.icanhazip.com、ifconfig.me/ip），不会把凭据放在子进程参数中。测试沿用现有四个服务、每站 15 秒的重试策略，可取消；整个测试可能超过 15 秒。

期望出口 IP 留空时使用代理入口 IP；若入口与出口不同，需要填写实际出口。IPv6 按地址值比较，避免缩写差异误报。修改地址、凭据或期望值后旧测试结果失效，添加/更新最终执行时也会重新测试。

完整检测成功证明该 SOCKS5/HTTPS 请求及出口匹配。当前没有独立的 RFC1929 认证探针，curl 不能告诉程序服务端是否实际选择了用户名/密码认证，所以结构化结果中的独立 authentication 状态保守为 unknown。检测也不证明真实应用域名路由或 UDP 出口正确。

ISP 只管理 `.env`、`config.json`；`clash.yaml` 不参与读取、备份或恢复。已有路由条件和顺序保留。移除遇到嵌套引用、`route.final: isp-socks`、detour 等依赖时会列出阻塞原因；不会擅自把策略改为 direct。TUI 首版对旧版或自定义入站要求先手动核对，不静默迁移。

## 失败恢复

### 首次部署

生成中的候选文件放在权限 0700 的 `.tui-stage-*` 目录，敏感文件权限为 0600。单文件采用原子写入，但四个目标文件不是一次跨文件原子事务。提交过程中失败会保留已经发布的配置与凭据，避免重试生成第二套密钥。

`.tui-operation.json` 记录操作阶段、已创建文件和状态，不含凭据正文。下次打开首页会提示未完成操作。四个部署文件完整且一致时，可预览后选择“启动并检查”，成功后更新操作记录。文件缺失或解析失败时先按诊断手动修复，TUI 不猜测重建策略。

强制终止后，临时目录可能仍含未发布的凭据；核对操作记录后按敏感文件处理。正常失败或取消会清理本次暂存目录。

### ISP 操作

执行阶段使用与 CLI 相同的 `.isp.lock`。配置变化时先校验候选，再备份两个托管文件，安装后只重建 Compose 中的 sing-box 服务并验证。仅 `.env` 变化和无变化有独立分支，界面不会把未检查的服务显示成健康。

安装、重启或检查失败会尝试恢复备份；文件恢复和服务恢复分别报告。恢复不使用原操作已经取消的 signal，避免中途取消导致恢复也立即停止。

`.tui-isp-operation.json` 是权限 0600 的无凭据恢复记录，包含阶段、备份位置、失败及恢复状态。检测到旧的 running 记录时会拒绝覆盖证据：先查看记录、备份和当前两个文件，再自行检查服务。核对完成后才手动处理该记录，程序不提供未经验证的自动跨进程回滚。不要直接删除 `.isp-backup`，其中可能是唯一恢复依据。

SIGINT、SIGTERM、SIGHUP 能请求停止并进入必要的恢复；SIGKILL 和掉电不能执行清理。正常退出会恢复光标、raw mode 与替代屏幕；若强制终止后终端异常，可运行 `reset`。

## 开发与验证

```bash
npm run typecheck
npm test
npm run build
node tools/check-bundle.mjs
node tools/check-pack.mjs
npm run license-scan
```

构建将 Ink、React 等代码内联进 CLI，保持 `dependencies` 为空。可选 React DevTools 入口从发布包排除，普通命令和库导入不会初始化 TUI。构建依据 esbuild 实际输入生成 `THIRD-PARTY-NOTICES.md`，包含已打包第三方代码的许可证。

具备 tmux 的开发机可运行真实 PTY 交互测试：

```bash
npm run build
TUI_PTY_TEST=1 npx vitest run tests/ts/tui-pty.test.ts
```

该测试实际启动生产 CLI 并操作新部署、密码隐藏/显示、ISP 添加和移除、缩放与退出。Docker、平台与出口查询由隔离替身提供，写入仅发生在新建临时目录，不能替代真实 VPS 验收。未显式启用时跳过此测试。

2026-11-03 本机 macOS / Node 26 的验证结果：全量测试 685 通过、9 失败、9 跳过；9 个失败在未修改的 HEAD 基线中完全复现，涉及系统 Bash 缺 mapfile、BSD head、Linux 平台前置条件及安装器的 sh 行为。独立真实 PTY 场景已通过。真实 Debian/Ubuntu Docker 部署及缺少外部二进制而跳过的运行时测试，仍需在支持环境验证。
