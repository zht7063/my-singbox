MY SING-BOX / TUI DESIGN

把部署所需的信息，放在同一个终端里。

通过状态首页、部署向导和 ISP 表单，让端口选择有检查依据，让每次保存与重启都有可核对的结果。

先把三条常用路径做好

入口建议为 my-singbox tui。不传子命令仍显示现有帮助；自动化继续使用现有 CLI。

首版包含

  • 运行条件逐项检测，提供原因和处理建议。
  • 首次部署确认服务器地址，选择 SS / VLESS 端口。
  • ISP 添加、更新、移除和主动测试。
  • 提交前预览，执行时显示阶段，完成后显示真实状态。
  • 已有部署查看端口、启动并检查、查看客户端导入说明。

后续再做

  • 已有部署修改端口：需要同时处理服务端和客户端迁移。
  • 多 ISP、路由编辑器、订阅与二维码。
  • 依赖自动安装、防火墙修改、卸载与镜像升级不在当前范围。

完整工程设计：仓库 docs/tui-design.md。本页为可浏览的原型与设计要点。

所有终端画面均为设计示意

检测结果、时间、任务状态和地址是演示数据。本页不连接服务器、不读取本机、不执行 Docker。保留地址仅用于说明；桌面画面可在手机中横向查看。

STATUS

检查结论有明确语义

OK / WARN / FAIL 表示结论；检查中、未检查、跳过、未知表示执行状态。未执行项不能算作通过。

ACTIONABLE

建议保留在当前上下文

选中一项就能看到处理建议。安装由用户自行执行；TUI 不调用 sudo。启用 ISP 后增加 curl 条件检查。

实施前置：现有 doctor 将 Compose v1 视为 WARN，但启动需要 v2，应统一；发行版识别、目录可写与 Docker context 也是新增检查。

VALIDATION

按协议检查

SS 同时检查 TCP 和 UDP，VLESS 检查 TCP。两个基础端口不能相同。修改字段后，旧的占用结果立即失效。

SUGGESTION

建议需要用户接受

候选高位端口检查后再展示；不自动替换已确认端口。提交前重查，最终仍以真实启动结果为准。

提示所依据的事实下一步
格式合法十进制整数，1–65535检查本机占用
未发现占用本次监听表或独占绑定检查提交前重查；启动后验证监听
未知工具缺失、权限或检查异常展示原因，预览中明确选择是否继续
外网未验证本地检查无法证明云安全组与公网可达自行放行，在客户端验证

CREDENTIALS

保留是一个明确动作

更新时不把星号填进密码框。选择更换后，新密码为空即报错。用户名和密码均必填，按 UTF-8 字节数验证。

EGRESS

期望出口是校验条件

留空默认校验入口 IP；入口与出口不同时填写真实出口。更换代理时提示确认旧期望值，不能把它当作备注。

输入边界

首版代理地址支持 IPv4 与严格 IPv6，主机和端口分开填写。不宣称支持域名代理、URL 或匿名认证。密码不 trim；引号、美元符号和反斜线由现有 env 序列化器处理。

状态分层

TCP 可连接、SOCKS5 认证和 HTTPS 出口检测分别报告。最终提交仍须通过出口校验；它不能证明实际应用域名路由正确。若 .env 与 config.json 凭据不一致，先显示来源差异。

更新保留现有 ISP 路由条件和顺序。移除遇到 route.final、detour、嵌套规则等残留引用时，列出路径并阻止操作；不擅自把策略改成 direct。

PLAN

不同操作，不同计划

首次部署创建四个文件。ISP 维护只涉及 .env 和 config.json，显示备份与服务动作；不把客户端文件列入事务。

COMMIT

确认时重新验证

草稿修改使旧计划失效。提交时加锁、重读文件与模板指纹；外部文件变化则要求重新预览。

ISP 的 config 变化需要保存并重启；取消不安装。仅 env 变化与无变化沿用现有分支，并准确展示是否检查过服务。首版不引入“保存但不应用”模式。

落地需要先接通的数据与业务层

TUI 与 CLI 共用校验、计划和应用服务。界面消费结构化事件，现有文本输出也由这些事件生成。

  CLI ─┐
       ├─ 应用服务：读取状态 → 校验草稿 → 计划 → 应用 → 验证
  TUI ─┘                 │
                         ├─ 核心：模型 / 渲染 / ISP / env / 脱敏
                         └─ 适配器：文件 / Docker / 端口 / 代理测试

  页面：加载 → 编辑 → 校验 → 预览 → 应用 → 验证 → 结果
                                              └─ 失败 → 恢复 → 结果
端口数据贯通
增加可选 SS_PORT / VLESS_PORT 环境键，缺失时仍是 8388 / 8443。服务端模板验证先检查原型再应用用户端口；客户端使用同一模型；UDP 检查改为按实际协议和端口生成。
结构化检查
提取 doctor 检查集合；增加发行版、目录、daemon 与 context 检查。缺 ss 是降级状态，缺 Compose v2 是部署阻塞。远程 Docker context 首版不支持部署，避免本地路径挂载误判。
ISP 用例抽取
当前事务编排在 CLI 私有闭包中。抽取共享用例，复用 IspService、纯配置变换、备份与安装原语。保留出口校验、候选校验、重启与恢复语义，消除对提示文本的依赖。
技术选择
先验证 Ink + React。构建依赖由 esbuild 内联，保持 npm 零外部运行时依赖。先整体打入 CLI；仅 tui 命令挂载界面，普通命令与库导入不得改变终端状态。
写入与中断
编辑不落盘；应用时共享写锁并校验基线。单文件原子写不等于多文件事务。持久记录执行阶段，不记录秘密正文；下次启动能识别未完成操作。恢复过程使用独立取消上下文。
凭据与输出
新旧秘密统一脱敏，处理跨输出块的泄漏与 ANSI 控制字符。文件 0600，私有目录 0700。正常退出和可处理信号恢复 raw mode、光标与屏幕；SIGKILL 无法保证恢复。
两处现有实现需要特别处理

普通启动的 UDP 检查写死 8388；自定义 SS 端口必须修正该路径。ISP 重建当前没有限定服务名，自定义 Compose 可能有额外服务；接入 TUI 前应限定 sing-box 或在预览中列明全部影响范围。

实施顺序与验收

先让业务结果可信，再完成界面；已有部署端口迁移独立推进。

阶段交付内容完成条件
P0 · 基础接口结构化检查与事件；Ink 打包和 SSH 技术验证零外部运行时依赖；正常 CLI 无副作用；中文、焦点和 resize 正常
P1 · 端口贯通env、模型、服务端与客户端渲染、启动检查默认兼容，自定义 SS UDP 检查正确；已有配置不被覆盖
P2 · 首版 TUI首页、完整向导、ISP 测试、预览与结果完成真实新部署和 ISP 维护；失败、恢复与中断准确呈现
P3 · 端口迁移已有配置增量更新、备份恢复、客户端重导入保留手改内容；服务端与客户端端口一致

终端交互验收

  • 纯键盘可完成流程；Enter 不从输入框直接提交。
  • 80 列单列；60–79 列逐字段紧凑模式。
  • 低于 60 列或 18 行给出 resize 提示；草稿保留。
  • 非 TTY 或 TERM=dumb 明确退出，指引使用 CLI。
  • 密码不回显；外部日志与错误一致脱敏。

业务验收

  • TCP 空闲但 UDP 冲突时仍拦住 SS 端口。
  • 已有文件、过期预览、并发写入不被覆盖。
  • ISP 操作使 clash.yaml 字节保持不变。
  • 文件恢复成功、旧服务恢复失败可同时显示。
  • typecheck、现有测试、build、bundle、pack、license 检查通过。
